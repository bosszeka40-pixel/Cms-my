# Missing CMS Functionality

## Текущее состояние проекта

- Базовый FastAPI backend в `backend/main.py`
- Управление ботом: `POST /api/bot/start`, `POST /api/bot/stop`, `GET /api/bot/status`, `POST /api/bot/simulate`
- AI-модуль и торговые стратегии: `backend/hft_brain.py`, `backend/modules/daily_harvester.py`, `backend/modules/strategy_manager.py`
- Модель `Plugin` и CRUD для плагинов в `backend/admin.py`
- Фронтенд: Jinja-шаблоны `templates/*.html`

## Отсутствующее функциональное ядро CMS

### 1. Маркетплейс плагинов

- Нет UI-страницы для просмотра доступных плагинов
- Нет API для получения каталога плагинов на стороне клиента
- Нет фильтрации/категорий платных и бесплатных модулей

### 2. Платные модули и покупки

- Нет механизма оплаты или интеграции платежной системы
- Нет статуса "покупка завершена" для плагина
- Нет логики, определяющей, какие плагины доступны бесплатно, а какие платно
- Нет истории заказов или счетов

### 3. Управление подключёнными модулями

- Нет механизма активации/деактивации плагинов
- Нет связывания плагинов с конкретным пользователем
- Нет проверки прав доступа при использовании платного модуля
- Нет загрузки плагина в бот или модуля расширения

### 4. Пользовательские роли и подписки

- Нет разделения ролей beyond `user` и `admin`
- Нет модели подписки, срока действия или тарифных планов
- Нет привязки доступа к модулям по подписке

### 5. CMS-интерфейс управления

- Нет полноценной панели управления плагинами
- Нет страницы маркетплейса
- Нет страницы управления покупками и оплатой
- Нет страницы со списком активированных модулей

### 6. Интеграции и расширяемость

- Проект содержит только один набор стратегий (`DailyCompoundHarvesterModule`)
- Нет архитектуры, позволяющей добавлять новые модули через плагины
- Нет механизма автозагрузки внешних плагинов или модулей

## Рекомендации для развития

- Добавить модель `PluginPurchase` / `UserPlugin`
- Добавить API:
  - `GET /api/plugins` — список плагинов
  - `POST /api/plugins/buy` — покупка плагина
  - `GET /api/user/plugins` — плагины пользователя
  - `POST /api/plugins/activate` — активация плагина
  - `POST /api/plugins/deactivate` — деактивация плагина
- Добавить UI:
  - `plugins.html` — маркетплейс
  - `user_plugins.html` — мои модули
  - `billing.html` — история покупок и подписки
- Добавить платёжную интеграцию для реальных покупок или mock-платёжную логику для прототипа
- Реализовать механизм прав доступа и проверки лицензии перед выполнением стратегии

## Итог

В настоящее время проект больше похож на прототип торгового бота с базовой CMS-структурой. Для полноценной CMS с платными модулями необходимо дополнить проект:

- UI маркетплейса и управления плагинами
- модель платных плагинов и привязку к пользователю
- платежный / лицензионный слой
- активацию/деактивацию модулей
- расширяемую архитектуру модулей
