# CMS strict audit

Дата начала: 2026-08-22

## Цель
Вернуть проект в рабочее состояние без удаления функционала.

## Проверка выполняется по слоям

1. Карта веток
- main
- рабочие ветки функционала
- security
- Netlify/deploy
- CMSC/Exchange
- тестовые ветки

Для каждой ветки фиксируется:
- commit
- изменённые файлы
- добавленный функционал
- риск слияния

## Карта функций

Проверяются:
- backend/main.py
- маршруты FastAPI
- admin
- bot
- exchange
- database
- templates
- static
- Netlify functions
- health/readiness
- тесты

## Карта связей

Проверка цепочки:
UI шаблон -> HTTP запрос -> FastAPI route -> service -> database/config -> ответ -> отображение шаблона

## Найденные проблемы на текущем этапе

1. Деплой Netlify проходил как готовый, но URL не открывал рабочую CMS.
2. Были расхождения между ветками и main.
3. Часть исправлений добавлялась поверх рабочего ядра без полного регрессионного теста.
4. Codespace запускался с копией файлов, которая не совпадала с ожидаемым состоянием main.
5. Нельзя смешивать функциональные изменения и изменения ядра без проверки маршрутов.

## Правило восстановления

Не удалять:
- CMSC
- Exchange
- security
- admin
- bot
- отчёты

Сначала восстановить базовый запуск, затем проверять каждый модуль отдельно.

## Следующие шаги

- полный список файлов
- проверка импортов
- проверка всех маршрутов
- проверка шаблонов
- проверка ответов API
- smoke запуск
- только после этого деплой.
