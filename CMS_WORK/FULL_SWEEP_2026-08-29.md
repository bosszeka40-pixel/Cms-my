## 2. Что именно проверено (подробно)

### 2.1 KPI-строка «Риск X/60»
- Разметка: `templates/dashboard.html:37` `· risk {{ risk_score }}/60`; карточка `dashboard.html:61-62` — значение `{{ risk_score }}/60`, цвет: `≤40` success, `≤60` warning, `>60` danger.
- Источники: `risk_score = risk_manager.calculate_risk_score(leverage=…)`, рендер серверный (`main.py` `start_bot`/`current_risk_score`). Литера «60» = `MAX_RISK_SCORE` (`backend/risk_management.py`).
- Проверка: страница показывала «DEMO · RISK **23/60**» (зелёное значение), `/api/risk/status` → `{current_risk_score: 23, max_risk_score: 60}` ✅. Живое соответствие.

### 2.2 Бот (полный жизненный цикл)
- Дефолт: `LIVE_CONTROL_STATE.global_kill_switch = True` (fail-closed by design).
- `POST /api/bot/start` при включённом килл-свитче → **423** «Сначала отключите аварийный выключатель» (в UI — browser `alert`, не «молча»).
- После `POST /api/risk/kill-switch {enabled:false}`:
  - `start` → `{status: started, risk_score: 23, lifecycle: RUNNING}`;
  - через ~8с `/api/bot/status` → `active:true, runs:2`, в `stats` появляются записи `started` и `test_trade`;
  - `stop` → `{status: stopped, lifecycle: STOPPED}` — ✅.
- Килл-свитч возвращён в ON.

### 2.3 Память бота — исправленный баг `NaN%`
- `GET /api/bot/memory` при пустой памяти возвращает `{total_trades:0, avg_pnl:0, best_trade:null, …}` **без ключа `win_rate`**; при непустой — `win_rate` уже в процентах (0..100).
- Шаблон (`bot_management.html:683`) делал `(d.win_rate * 100).toFixed(1)` → `undefined*100 = NaN` (пустая память) и дал бы 5000% (непустая). `signColor((d.win_rate||0) - 0.5)` тоже рассчитывал на дробь 0..1.
- Фикс: `(d.win_rate ?? 0).toFixed(1) + '%'` и `signColor((d.win_rate ?? 0) - 50)` — согласовано с процентами из API. После фикса: «Винрейт 0.0%», NaN исчез со всех страниц.

### 2.4 Бэктесты (strategies, testing)
- `POST /api/bot/backtest` → 400-подмножество отвечает мгновенно (невалидная пара, отрицательный баланс).
- Полный путь: `refresh_history` (внешний fetch 1-дневных свечей, HISTORY_DAYS=365) + `_exchange_fee_rate` (ещё `load_markets()`, вызывается ДВАЖДЫ) + `evaluate_strategies` (30 стратегий, чистый CPU).
- В-процессе: refresh ~5с, evaluate ~6с — **функционально работает**.
- По HTTP на сервере биржа (binance) троттлит этот IP: refresh 25–90с, evaluate ещё ~30с (замерено инструментальными логами: `refresh done 59.2s`, `evaluate done 90.4s`). Generate-эндпоинт (тот же refresh) — 8–25с.
- UI: «⏳ Выполняется backtest…» / «⏳ Загрузка рыночных данных…» без индикатора прогресса и без таймаута; `#test-chart` canvas создаётся только после завершения. При нескольких таких запросах пул воркеров saturates → сайт периодически перестаёт отвечать (наблюдались таймауты даже на `/login` и `/marketplace`).

### 2.5 Демо
- `POST /api/demo/trade`: валидация, стратегия из `strategy_manager`, P/L по части баланса (`allocation = amount/balance`).
- Авто-демо (клиент, `demo.html:186-196`): каждые 5с `price_change = Math.random()*6 - 3` (±3%), sentiment случайный; телефонный сигнал long только если `sentiment>0 и price_change>0` (`daily_harvester.process_tick`), иначе шорт.
- Наблюдение: за прошлые проверки демо-баланс спущен со 100 до ~0.0004€ (309 сделок, P/L ≈ −100€ — баланс хранится в БД и «слив» переживает перезапуски). После рестарта в памяти счёт 100, но запрос идёт к БД — всё ещё ~0. При нулевом балансе manual-сделка даёт P/L 0.0000 (корректный no-op).

## 3. Найденные проблемы (и рекомендации)

### 3.1 (ИСПРАВЛЕНО) NaN в `#bot-memory` — `templates/bot_management.html`
Причина: отсутствие ключа `win_rate` в ответе при пустой памяти + умножение на 100. Исправлено.

### 3.2 Авто-демо — гарантированный «слив» баланса (demo.html + backend)
Комиссия за тик: `fee = balance * leverage * fee_rate * 2` ≈ **0.3% баланса каждые 5с**; сигнал long лишь при двух условиях одновременно → матожидание отрицательное. Итог: 5-минутный тест уничтожает демо-счёт. Рекомендации (по вкусу):
- снизить/убрать комиссию для автоматических демо-тиков;
- сделать `price_change` маленьким (±0.5%) или преобразовать в % (сейчас `price_change/100` двоит масштаб: на вход ±3% → trade_return до ±4.5% × leverage);
- симметричный сигнал long при `price_change>0` независимо от sentiment.

### 3.3 Бэктесты медленные + «заморозка» сайта при пачках запросов
Внешняя биржа троттлит IP → refresh/load_markets 30–120с; UI без прогресса; воркеры залипают → непрогруз всех страниц. Рекомендации:
- выставить таймаут внешнего fetch (например 15с) и кэшировать `load_markets` (сейчас `_exchange_fee_rate` зовёт его 2 раза);
- на фронте — индикатор прогресса/таймаут кнопки «Запустить тест».

### 3.4 Асимметрия kill-switch (`main.py:1863-1871`)
`POST /api/risk/kill-switch {enabled:true}` ставит `kill_switch=true`, но `LIVE_CONTROL_STATE.global_kill_switch` остаётся `false` (global выставляется только при `enabled:false`). Ответ `/api/risk/kill-switch` показывает `kill_switch:true` при `global_kill_switch:false`. При этом `start_bot` проверяет ОБА слоя (безопасно), а `/api/trading/manual` — только `LIVE_CONTROL_STATE.allows(...)` → при выключенной risk-аварийке и включённом bot_live manual live-сделка была бы возможна. Рекомендуется синхронизировать оба слоя в одну сторону (или чтобы `enabled:true` включал global тоже).

### 3.5 Прочее
- `GET /api/copy-trading/settings` → 405 (эндпоинт POST-only) — это не баг, но страница не вызывает его на GET-методе.
- Консольные 404 = `/favicon.ico` (не влияет); 423 = ожидаемые ответы start-бот при включённом kill switch.
- `toggleCopy()` в copy_trading.html чисто UI-клик (не пишет в API); сохраняемой модели нет — стоит решить, нужно ли.
